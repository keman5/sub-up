### 2026-06-13 前台长有效期 token 触发浏览器定时器上限导致 refresh 风暴

线上现象：a2 登录成功后仍会在极短时间内持续请求 `/api/v1/auth/refresh`，后端先返回 200，随后被 refresh-token 限流打到 429。本地复现时登录响应 `expires_in=2592000`（30 天），后端日志显示登录后没有先出现业务接口 401，却在同一秒内连续出现几十次 `/api/v1/auth/refresh`。

根因：前端 `scheduleTokenRefreshAt()` 直接把 `expires_at - now - 120s` 交给 `setTimeout`。30 天 access token 的延迟超过浏览器 `setTimeout` 最大安全延迟（约 24.8 天），浏览器会把超长延迟夹成近似立即执行，导致“refresh 成功 -> 重新安排 30 天定时器 -> 立即触发 -> 再 refresh”的循环。

本地补丁：

- `frontend/src/stores/auth.ts`：新增 `MAX_TOKEN_REFRESH_DELAY=24h`，超长主动刷新延迟改为分段等待；每段醒来后重新计算是否已进入 120 秒刷新缓冲区，未到期则继续分段等待，到期才调用 `performTokenRefresh()`。
- `frontend/src/stores/__tests__/auth.spec.ts`：覆盖 30 天长有效期 token 登录后 60 秒内不应触发主动 refresh，防止浏览器定时器上限导致回归。

## 2026-06-30: 管理员邮件提醒补强

**本地补丁：**

- 订阅过期任务仍每分钟扫描并将刚从 `active` 更新为 `expired` 的订阅作为唯一通知来源，但管理员提醒不再对每个过期订阅逐条发送邮件。
- 新增 10 分钟内存聚合窗口：本轮刚过期的订阅会先进入窗口，窗口到期后的下一轮扫描按管理员收件人发送一封列表邮件，邮件正文包含每个过期订阅的订阅 ID、分组、过期用户邮箱、用户备注和过期时间；用户备注为空时再显示用户名作为辅助信息。
- `subscription.expired_admin` 邮件模板新增 `expired_count` 与 `expired_subscriptions` 占位符；`expired_subscriptions` 仅在该事件中允许作为受控 HTML 表格插入，表格单元格内容会转义，避免用户邮箱、用户名或分组名注入 HTML。
- 保留原有安全边界：管理员提醒默认关闭；收件人仍来自 `subscription_expired_admin_notify_emails` 且只发送给已确认邮箱；旧的单条占位符继续保留，便于自定义模板兼容。
- 新增 `AccountPoolHealthNotifyService` 后台巡检，每分钟分页读取全部账号并复用 `ListSchedulable()` 判定可调度账号数。账号总数大于 0 且可调度数为 0 时，向 `account_quota_notify_emails` 中已验证邮箱发送 `account.pool_unavailable` 管理员邮件，正文包含账号 ID、名称、平台、状态、调度开关和备注；使用 `account_pool_unavailable_outage_id` 作为一次性栅栏，故障持续期间只发送 1 次，恢复到至少 1 个可调度账号后清除栅栏，下一次全不可用可再次告警。
- `account.pool_unavailable` 邮件模板新增 `account_count`、`checked_at`、`accounts` 占位符；`accounts` 仅在该事件中允许作为受控 HTML 表格插入，账号名称、状态、备注等字段继续 HTML 转义。空账号池不会发送“全不可用”邮件，避免新环境尚未配置账号时误告警。
