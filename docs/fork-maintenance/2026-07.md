## 2026-07-05: 客户故障排查助手

**本地补丁：**

- 新增 `TroubleshootingAssistantService`，统一处理用途限制、输入截断、系统证据查询、本地规则诊断、限流和 AI 诊断兜底。
- 新增 Redis 限流器：单用户 5 分钟最多 10 次、每日最多 50 次，命中后返回 429，不进入 AI 调用。
- 新增 `SystemTroubleshootingEvidenceProvider`：优先用 request id 查询系统请求详情，并读取当前 OpenAI 账号池可用状态；如果查到明确错误日志或当前账号池已恢复，直接返回 `排查结果`，不再输出多个“可能原因”；输出按结论动态组合，不使用固定四段模板；如果判断暂不需要管理员处理，不输出“是否需要联系管理员/暂时不需要联系管理员/建议提供给管理员的信息”等冗余段落，AI 返回这类模板残留也会被后端过滤。
- 新增 OpenAI AI 诊断客户端：从可用 OpenAI 账号中最多尝试 3 个；OAuth 账号优先使用已映射的 `gpt-5.3-codex-spark`，未配置映射时也默认使用该 Spark 模型，避免故障排查走 `gpt-5.5` 导致响应过慢；ChatGPT internal `/backend-api/codex/responses` 请求不发送不兼容的 `max_output_tokens` 参数，AI 请求超时为 30 秒。

- 新增认证用户接口 `POST /api/v1/troubleshooting/analyze`。
- 新增认证用户接口 `POST /api/v1/troubleshooting/notify-admin`；只有诊断结果需要管理员处理时前端才显示 `通知管理员` 按钮。点击后提示 `已通知管理员，请等待 5 分钟后重试。`；后端对该接口再次校验“只能排查请求失败”，并复用故障排查用户限流，避免直接调用通知接口刷管理员邮件。

## 2026-07-05: 错误响应与故障排查输出跟随界面语言

**本地补丁：**

- 前端请求已统一携带 `Accept-Language`，后端 `response.ErrorFrom` 在输出结构化错误时根据该 header 和 `reason` 替换展示用 `message`。
- 后端 `response.Error` / `response.ErrorWithDetails` 同步接入本地化，覆盖历史 handler 里大量直接返回的英文消息。
- 新增 `localizedErrorMessages` 首批覆盖认证、OAuth pending、订阅、故障排查、故障排查通知、运维错误日志、Turnstile、TOTP、兑换码等常见结构化错误。
- 新增 `localizedDirectErrorMessages` 和通用规则，覆盖 `Invalid ... ID`、`Invalid request: ...`、未登录、无权访问、服务未配置、功能未启用、请求体为空/读取失败、图片生成分组禁用、图片接口参数校验等常见直接响应。
- 新增兼容客户端错误消息本地化 helper，保持 OpenAI / Claude / Gemini 兼容响应结构不变，仅根据 `Accept-Language` 翻译本地生成的错误 `message`；上游原始错误不匹配本地规则时继续原样返回，避免影响客户排查。
- 未收录的 `reason` 继续返回原始 message，避免丢失动态错误详情；`reason` 与 `metadata` 字段保持不变，前端仍可按错误码做专门交互。
- 故障排查助手从 handler 传入 `Accept-Language`，本地规则、系统证据、AI 不可用提示和 AI prompt 均按语言输出；默认空语言仍保持中文。
- 管理员订阅进度接口不再把所有错误固定包装成 `Subscription not found`，真正订阅不存在仍返回 `SUBSCRIPTION_NOT_FOUND`，底层仓库/数据库错误原样透传。
- OpenAI gateway 的图片生成分组禁用响应不经过统一 `response.Error`，单独接入 `Accept-Language`，中文环境返回 `当前分组未启用图片生成`。
